# 架构与通信协议

本文档面向开发者，描述插件的内部架构和模块间通信机制。

## 整体架构

```
Photoshop UXP 宿主环境
├── index.html（入口）
│   ├── <webview src="panel.html">  ← 前端 UI
│   └── <script src="index.js">     ← 后端 Host
│
├── 后端模块
│   ├── index.js          ← 核心（5000+ 行）：PS 操作、API 调用、文件 I/O
│   ├── host/router.js    ← 消息路由分发
│   ├── host/context-builder.js  ← 依赖注入上下文（100+ 属性）
│   ├── host/bootstrap-handlers.js
│   ├── host/high-risk-task-handlers.js
│   ├── host/low-risk-handlers.js
│   ├── host/misc-handlers.js
│   ├── host/selection-flow-handlers.js
│   ├── host/stop-control-handlers.js
│   ├── host/recordable-actions.js
│   ├── host/concurrency-pool.js
│   ├── login-service.js   ← 云服务认证
│   └── workflow-engine.js ← ComfyUI 工作流解析
│
└── 前端模块
    ├── panel.html    ← UI 布局 + CSS（3200+ 行）
    ├── panel.js      ← App 框架（状态管理、消息路由、Tab 切换）
    ├── panel-init.js ← 启动触发
    ├── tab-generate.js  ← 生成 Tab
    ├── tab-chat.js      ← 聊天系统
    ├── tab-settings.js  ← 设置 Tab
    ├── tab-advanced.js  ← 高级功能 Tab
    ├── tab-forge.js     ← Forge Tab
    ├── tab-batch.js     ← 批处理 Tab
    ├── tab-comfyui.js   ← ComfyUI Tab
    ├── cloud-panel.js   ← 云服务面板
    ├── preset-body.js   ← 人体剪影预设选择器
    ├── preset-search.js ← 预设搜索
    └── preset-body.css  ← 人体剪影样式
```

## 前后端通信

### 前端 → 后端

```js
App.sendToHost(action, data);
// 封装为 { source: 'panel', action: '...', data: {...} }
// 通过 window.uxpHost.postMessage 发送
```

### 后端 → 前端

```js
sendToPanel(action, data);
// 封装为 { source: 'host', action: '...', data: {...} }
// 前端通过 App.onMessage(action, handler) 接收
```

### 路由机制

后端收到消息后经过 `host/router.js` 按优先级分发：

```
bootstrap-handlers → low-risk-handlers → selection-flow-handlers
→ high-risk-task-handlers → stop-control-handlers → misc-handlers
```

## 关键消息列表

### 生成流程

| 方向 | 消息 | 数据 |
|------|------|------|
| → Host | recordableRunSingle | taskId, prompt, apiKey, model, size, batchSize, timeout, refImages, provider |
| ← Panel | taskProgress | taskId, total, index, status(success/fail) |
| ← Panel | taskComplete | taskId, successCount, size, model, cached |
| ← Panel | taskReturned | taskId |

### Forge 流程

| 方向 | 消息 | 数据 |
|------|------|------|
| → Host | forgeImg2Img | prompt, negPrompt, steps, cfg, denoise, resolution, model, sampler, ... |
| ← Panel | forgeProgress | progress(0-1), done, taskId |
| ← Panel | forgeComplete | taskId |

### 控制消息

| 方向 | 消息 | 数据 |
|------|------|------|
| → Host | earlyStopTask | taskId |
| → Host | extendTimeout | seconds |
| → Host | returnTaskResult | taskId |
| → Host | setTaskAutoReturn | taskId, autoReturn |

## PS 操作串行锁

所有 PS 操作通过 `acquirePSLock(fn, taskId)` 串行化，防止并发操作冲突：

```
任务1 acquirePSLock → 执行 → 200ms 冷却 → 任务2 执行 → ...
```

## IPC 卫星通信

主插件通过文件系统与卫星插件（轮椅遥控器）通信：

```
主插件 → wheelchair_ipc/state.json → 遥控器读取（500ms 轮询）
遥控器 → wheelchair_ipc/command.json → 主插件读取（500ms 轮询）
```

### state.json 结构

```json
{
  "ts": 1234567890,
  "globalAutoReturn": true,
  "tasks": {
    "t_xxx_abc": {
      "label": "模型名 ×数量",
      "batchSize": 2,
      "success": 1,
      "fail": 0,
      "percent": null,
      "countdown": 85,
      "autoReturn": true,
      "awaitingReturn": false,
      "status": "running"
    }
  }
}
```

## 状态持久化

通过 `storageGet/storageSet` 存取，后端在 `getDataFolder()` 下以 JSON 文件持久化。前端通过 `sendToHost('storageSet', {key, value})` 触发保存，有 500ms 去抖。

启动时后端发送 `storageLoaded` 消息将所有 KV 数据一次性传给前端。
