# 去云化评估：彻底移除云服务，独立为纯本地插件

> 状态：**评估阶段，尚未动代码。** 基线 6.6.4（`main` @ 3bae6f2）。编写于 2026-10-24。
> 本文所有结论均来自对源码的逐处核对（grep 全部 `/api/*`、`/auth/*` 路径与 `server-config.js` 引用），文件行号以 6.6.4 为准。

## 1. 目标与前提

- **目标**：删掉所有依赖作者后台（`xiasanqi.cpolar.top` / `xiasanqiforge.vip.cpolar.cn` / `qwentest.vip.cpolar.top`）的功能，包括账户、积分、遥测、客服、更新、云同步；插件完全不再连接作者的任何服务器。
- **保留**：用户自带 Key 的第三方服务商（AJI / GRS / Momo / Others）、本地 Forge、本地 ComfyUI、全部本地预设/布局/知识库。
- **前提（用户告知，未在本仓库核实）**：作者已宣布闭源、停止更新、停止云服务。README 目前仍写「作者尚未闭源」，待补充公告来源后更新。
- **授权**：GPL v3 对已发布版本不可撤销，fork 改造合法；须保留许可头、继续 GPL v3、在 README 载明修改（第 5(a) 条）。
- **系统提示词**：作者放在服务端的提示词（翻译 / 提示词优化 / 海报自动填充）用户已有备份，不构成阻塞。
- **名称（已定）**：沿用 **ps-banana**，不使用「修图轮椅」「夏三七」。
- **定位（已定）**：作为新插件发布，**不迁移老用户的本地设置**。

## 2. 结论摘要

**可行，难度中等偏低。** 理由：

1. 核心出图链路 `tile-run` → `host/ai-api.js` 的 `callAiApi()` 直连用户配置的服务商，**不经作者后台、不扣积分**。只有「云 Forge」分支先调 `apiConsumePoints`（`tiles/tile-run.host.js:720`）。
2. 未登录时只冻结云功能磁贴（同步、服务状态、提示词优化、更新、客服），主界面不需要登录。
3. 磁贴是自动发现加载（`tiles/_order.json` 未列出的按字母序追加），出厂布局里也没有引用待删磁贴，**整块删磁贴比较干净**。
4. 两个配套插件（轮椅浏览器 / 轮椅遥控器）没有任何后端调用，不用改。

**需要提前知道的一个问题**：GRS + GPT-Image 的图生图路径会把用户的图片先传到作者的临时图床（见 §5.1），停服后这条路径即使用 BYOK 也会断。**2026-10-26 已用真实 Key 实测解决：GRS 新接口官方支持直接传 base64，改用新接口即可，不再需要图床。**

## 5. 风险与待验证项

### 5.1 GRS + GPT-Image 图生图依赖作者图床（已实测解决，定为方案 2）

**现状**：`tiles/tile-run.host.js:627-650`。走 GRS + GPT-Image 且带图时：

```
PS 选区 / 参考图 (base64)
  → 强制压缩到 1.2MB 以下（注释：防 cpolar 转发 502，服务端上限 2MB）
  → _uploadRefsToTempServer() 上传到作者的 /api/poster/upload-temp，换回公网 URL
  → 填进 payload.urls，提交给 GRS 旧接口 /v1/draw/completions
```

海报磁贴（`tile-poster.host.js:139`、`:690`）也是同一套流程。作者认为旧接口 `urls` 只收公网 URL（`host/ai-api.js:824` 注释），所以借自己的服务器当临时图床。停服后这条路径即使 BYOK 也会断，而且断得很隐蔽：`host/ai-api.js:1297` 拿不到 URL 时只打警告、**忽略参考图继续出图**。

影响范围只有「GRS × GPT-Image × 带图」。GRS 的 Banana 模型和纯文生图不受影响。

**实测（2026-10-26，Windows 端，真实 Key，`gpt-image-2-vip` 1K，4 张图共 8000 积分）**：

| 接口 | 参考图字段 | 结果 |
|---|---|---|
| 旧 `POST /v1/draw/completions` | `urls: ["data:image/png;base64,…"]` | 单图、双图都成功 |
| 新 `POST /v1/api/generate`，`replyType` 不传（同步） | `images: [data URI]` | 成功，约 33s 直接返回结果 URL |
| 新接口，`replyType: "async"` | `images: [data URI]` | 成功，提交即返回 id，轮询 `GET /v1/api/result?id=` 约 40s |

判定方式是对结果图做像素颜色占比（测试图红块被改成蓝块、双图时红绿都在），确认模型确实读到了参考图。脚本：`tools/grs_probe.py`（原始记录见 git 历史中的 `win-test` 分支提交 `e14e347`）。

**决定：方案 2，换新接口 + `replyType: "async"`**（2026-10-26 定）。

- 理由：新接口的 `images`「支持 base64 与 url」是**官方文档写明的**（Apifox：<https://qmy27nhsd9.apifox.cn/452409160e0>）；旧接口 `urls` 收 base64 只是实测能用、没有文档承诺。万一以后收紧，最可能的表现是参考图被悄悄忽略，代码察觉不到、还照样扣费。异步模式也避开了 4K / 排队时单次请求超时的问题。
- 做法：`callGrsGptImageApi` 改为 `POST {base}/v1/api/generate`（`images` 填 data URI，`replyType: "async"`）→ 轮询 `GET {base}/v1/api/result?id=`；删掉 `_uploadRefsToTempServer`，tile-run 和海报两处一起改。
- 工作量：0.5–1 天，含回归。
- 附带收益：用户图片不再经过任何中间服务器；不再需要 `support.deviceId`。

**新接口要点（官方文档，2026-10-26）**：

| 项 | 内容 |
|---|---|
| 节点 | `https://grsai.dakka.com.cn`（国内，插件默认）/ `https://grsaiapi.com`（全球）。`dakka.com.cn` 是 GrsAI 开票主体「打卡（广州）科技」注册的，与作者无关 |
| 响应 | `{id, status, results:[{url}], progress, error}`；`status` 为 `running` / `succeeded` / `failed` / **`violation`（也按失败处理）** |
| 同步模式的 id | 不落记录，`/v1/api/result` 查不到（404），所以要轮询就必须用 `async` |
| `aspectRatio` | `gpt-image-2` / `2.5` 收比例或像素值；`-vip` / `-flare` / `-sunburst` **只收像素值**（最长边 ≤3840，边长为 16 的倍数，长短边比 ≤3:1） |
| `quality` | 各模型可选值不同，`gpt-image-2` 只有 `auto`，`-vip` 只有 `medium` |
| 结果 URL | 有效期 2 小时，要及时取回 |
| 计费 | 1K `gpt-image-2-vip` 每张 2000 积分（¥1 = 20000 积分） |

**还没验证的**（改造时一并测）：

1. 请求体上限：实测只用了几 KB 的图。第一版**保留现有 1.2MB 压缩**，链路通了再单独测能放宽到多少。
2. JPEG 参考图、4K 输出：未测。
3. 真实照片（人像等）的审核策略：未测，`violation` 状态要给用户可读的提示。

## 6. 安全上为什么必须彻底删

后台是 cpolar 内网穿透的二级域名。作者停服后如果放弃这个域名，**有可能被他人注册**（cpolar 的回收政策未核实）。真被接管的话，旧代码会：

1. 把用户的邮箱和密码发到对方服务器（`login-service.js:208`）；
2. 对方能伪造登录态，之后 `tile-update` 会从 `/api/update/download` 下载 zip，并拉起 `update_plugin.bat` 执行（插件声明了 `launchProcess` 权限）；
3. 携带 `cloud.token` 的请求、客服消息、用户上传的图片都会流向对方。

所以去云化不只是功能清理，同时也是安全修复。只改 `OFFICIAL_BASE` 指向空地址不够，必须连调用链一起删。
