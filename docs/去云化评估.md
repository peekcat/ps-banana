# 去云化评估：彻底移除云服务，独立为纯本地插件

> 状态：**评估阶段，尚未动代码。** 基线 6.6.4（`main` @ 3bae6f2）。编写于 2026-10-24。
> 本文所有结论均来自对源码的逐处核对（grep 全部 `/api/*`、`/auth/*` 路径与 `server-config.js` 引用），文件行号以 6.6.4 为准。

## 1. 目标与前提

- **目标**：删掉所有依赖作者后台（`xiasanqi.cpolar.top` / `xiasanqiforge.vip.cpolar.cn` / `qwentest.vip.cpolar.top`）的功能，包括账户、积分、遥测、客服、更新、云同步；插件完全不再连接作者的任何服务器。
- **保留**：用户自带 Key 的第三方服务商（AJI / GRS / Momo / Others）、本地 Forge、本地 ComfyUI、全部本地预设/布局/知识库。
- **前提（用户告知，未在本仓库核实）**：作者已宣布闭源、停止更新、停止云服务。README 目前仍写「作者尚未闭源」，待补充公告来源后更新。
- **授权**：GPL v3 对已发布版本不可撤销，fork 改造合法；须保留许可头、继续 GPL v3、在 README 载明修改（第 5(a) 条）。
- **系统提示词**：作者放在服务端的提示词（翻译 / 提示词优化 / 海报自动填充）用户已有备份，不构成阻塞。
- **名称（已定）**：沿用 **ps-banana**，不使用「修图轮椅」「夏三七」。
- **定位（已定）**：作为新插件发布，**不迁移老用户的本地设置**。

## 2. 结论摘要

**可行，难度中等偏低。** 理由：

1. 核心出图链路 `tile-run` → `host/ai-api.js` 的 `callAiApi()` 直连用户配置的服务商，**不经作者后台、不扣积分**。只有「云 Forge」分支先调 `apiConsumePoints`（`tiles/tile-run.host.js:720`）。
2. 未登录时只冻结云功能磁贴（同步、服务状态、提示词优化、更新、客服），主界面不需要登录。
3. 磁贴是自动发现加载（`tiles/_order.json` 未列出的按字母序追加），出厂布局里也没有引用待删磁贴，**整块删磁贴比较干净**。
4. 两个配套插件（轮椅浏览器 / 轮椅遥控器）没有任何后端调用，不用改。

**需要提前知道的一个硬问题**：GRS + GPT-Image 的图生图路径会把用户的图片先传到作者的临时图床（见 §5.1），停服后这条路径即使用 BYOK 也会断，要另找办法。

## 5. 风险与待验证项

### 5.1 GRS + GPT-Image 图生图依赖作者图床（阻塞项）

`tiles/tile-run.host.js:627-650`：走 GRS + GPT-Image 时，主图和参考图会先通过 `_uploadRefsToTempServer()` 上传到 `/api/poster/upload-temp`，换成外网 URL 再交给 GRS。海报磁贴（`tile-poster.host.js:139`、`:690`）也一样。

- 停服后这条路径**即使是 BYOK 也会失败**。
- 隐私问题：用户的图片原本就会经过作者服务器。
- 鉴权用的 `support.deviceId` 由客服磁贴生成（报错文案：「请先打开过客服磁贴」），删客服后要一起处理。
- **待验证**：GRS 的 GPT-Image 接口是否接受 base64 直传。如果接受就改成直传；不接受的话，要么接入用户自己的图床（S3 / R2 / 其他），要么放弃这个组合。这一项的工作量只有验证后才能确定。

### 5.2 其他

- **没有自动化测试**。每一步都要在 Photoshop 里用 UDT 加载、手动回归，这是工期的主要不确定因素。
- **插件 ID**：现为 `com.xiasanqi.ps.wheelchair.v4`（`manifest.json:2`），与作者后续闭源版本会撞 ID、共用存储。建议改成自有 ID（具体 ID 待定）。已定不迁移老设置，所以换 ID 没有额外成本。`canvas-pkg/cv-gen.js:17`、`host/recordable-actions.js:11` 和遥控器里写死了主插件 ID，要一起改。
- **`defaults/v5-data-migration.js`**：这是作者从 v5 迁到 v6 用的迁移代码。我们不做迁移，换 ID 后它就没用了，可以随 D 阶段一起删。
- **用户残留数据**：老存储里有 `cloud.token`、`login.savedPassword`（`GPTdev.md` §22 提到面板存储会存密码）。**换了 ID 就读不到老存储，这条自然消失**；如果最后决定沿用原 ID，就要在首次启动时清掉这些数据。
- **`GPTdev.md` 部分过时**：比如有道 Key 那条。以源码为准。

## 6. 安全上为什么必须彻底删

后台是 cpolar 内网穿透的二级域名。作者停服后如果放弃这个域名，**有可能被他人注册**（cpolar 的回收政策未核实）。真被接管的话，旧代码会：

1. 把用户的邮箱和密码发到对方服务器（`login-service.js:208`）；
2. 对方能伪造登录态，之后 `tile-update` 会从 `/api/update/download` 下载 zip，并拉起 `update_plugin.bat` 执行（插件声明了 `launchProcess` 权限）；
3. 携带 `cloud.token` 的请求、客服消息、用户上传的图片都会流向对方。

所以去云化不只是功能清理，同时也是安全修复。只改 `OFFICIAL_BASE` 指向空地址不够，必须连调用链一起删。

## 7. 本地 ComfyUI / Forge 支持情况

| | 支持情况 | 证据 |
|---|---|---|
| **本地 ComfyUI** | **完全支持，且与云端零耦合** | `tiles/tile-comfyui.*` 默认 `http://127.0.0.1:8188`，可改地址；不引用 `server-config`，也没有任何登录判断。功能：连接、读取工作流文件夹、加载工作流、生成、中断 |
| **本地 Forge** | **支持**，和云 Forge 共用一个磁贴 | `tiles/tile-forge.js` 有「本地 / 云」切换，本地默认 `http://127.0.0.1:7860`；走标准 `/sdapi/v1/*`（img2img、txt2img、模型、采样器、ControlNet、LoRA、中断）。`login-service` 在这里是 `try/require` 可选依赖（`tile-forge.host.js:67`），注释写明「未装云服务也不影响本地」 |

改造时 ComfyUI 不用动；Forge 只需去掉「云」按钮和相关状态显示（`tile-forge.js:280-400`、`:603-612`），固定为本地。地址可以填局域网或自建服务器，不限于本机。

## 8. 工作量拆分（粗估）

估算前提：一人、熟悉 JS、可以随时在 PS + UDT 里手动回归；**不含**上手读代码的时间。数字只是量级参考。

| 阶段 | 内容 | 粗估 |
|---|---|---|
| A. 删除 | 删 §3.1 的 7 个磁贴和 `login-service` / `tile-cloud`；手术式清理 `tile-topbar` / `tile-params` / `tile-forge` / `tile-api` / `tile-run`；遥测换成空桩；§3.3 小改；清理残留存储 | 3–5 天，大头在 `tile-topbar` 和回归 |
| B. BYOK 化 | 翻译、提示词优化、海报自动填充改为直连 LLM，接回备份的提示词；设置里加「辅助 LLM」配置项（或复用 Others 配置） | 1–3 天 |
| C. GRS 图床 | 先验证 base64 直传（§5.1），再决定方案 | 验证 0.5 天；后续 0 到 2 天以上，视结果而定 |
| D. 独立化 | 改名为 ps-banana（`manifest.json` 的 `name`、界面标题）、改插件 ID 及各处写死的 ID、删 v5 迁移代码、配套插件同步、README 修改声明、更新 `GPTdev.md` | 1 天，不含迁移代码 |

合计约 **1–2 周**，最大变数是 C 和手动回归。

建议的顺序：**A → 验证 BYOK 出图、本地 Forge、本地 ComfyUI 全部正常 → C → B → D**。每个阶段单独成一组提交，`upstream` 分支保持不动，方便随时和原版 diff。
