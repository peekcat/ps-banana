## 任务 1：一个公用的 LLM 调用函数

三个功能都是「拼 system + messages，POST `/v1/chat/completions`，取 `choices[0].message.content`」。**写一份，三处共用**，不要复制三份。

- 位置：新建 `host/aux-llm.js` 一类的 host 模块（名字可以自定，计划里写明）。
- URL 规范化：照抄 `tiles/tile-light-splitter.host.js` 的 `_normalizeChatUrl`。最好让拆光也改用这份；如果不想扩大改动，计划里说明原因，这一轮只给三个新功能用。
- 非流式，`stream: false`；超时 120 秒左右（原提示词优化留了 320 秒，那是作者服务端开思考模式的需要，我们不用照搬）。
- 错误要能看懂：401 / 402 / 404 / 429 照拆光那份的提示，网络失败、超时、返回里没有 `content` 各给一句人话。**不要把整段原始响应甩给用户**，最多截 200 字附在后面。
- **配置怎么到 host**，选一种，三处都用同一种，计划里说明：
  - 照拆光的做法，面板从 `TileAPI.storage` 读 `chat.*` 一起发给 host（`tile-prompt.js`、`tile-forge.js`、`tile-prompt-optimizer.js`、`tile-poster.js` 四处发起点都要改）；
  - 或者 host 直接从 host 存储读 `chat.*`（先确认这些 key 在 host 侧确实读得到）。

## 任务 3：写提示词

**放在一个地方**：建议新建一个文件集中放三类提示词（例如 `host/aux-prompts.js`），以后调效果只改这一个文件。文件头写明「本项目自行编写，GPL v3」。

**翻译**

- 用途：把中文（或混合）描述翻成**英文出图提示词**，结果会被追加到正向 / 反向提示词里。
- 要求：只输出译文，不加引号、解释、前后缀；保留原有的逗号分隔结构；**原样保留**权重和特殊语法，例如 `(word:1.2)`、`[word]`、`<lora:name:0.8>`、`BREAK`；已经是英文的部分不改。
- `temperature` 取低值（0–0.3）。

**提示词优化**

- 用途：用户写一句大白话（例：「把人变好看点」），扩写成结构化的出图提示词；之后用户可以追问（例：「再强调一下光影」），模型在上一版的基础上改。
- 要求：每次只输出**完整的最终提示词**，不要寒暄、解释，不要用 Markdown 标题；追问时输出改完后的完整一版，不要只输出差异。
- **待使用者定**：输出用中文、英文，还是跟随用户输入的语言。GRS 的 Banana / GPT-Image 都能读中文。计划里把这个问题列出来，让使用者选。

**海报自动填充**（两个类别：`commission` 接单图排版、`portfolio` 作品集排版）

- 用途：用户粘贴一段文案（例如接单价目、联系方式、风格说明），模型把它拆进海报磁贴的各个表单项。
- **字段定义不要写死在提示词里**，要在运行时从 `window._posterPrompts[cat].sections` 生成。理由：使用者可以在管理预设面板里改这些选项，写死就对不上了。做法：面板发 `posterAutofill` 时把当前类别的 `sections` 精简后一起发过去，只要 `id`、`label`、`type`，以及 `buttons` 的 `id` 和 `label`；host 据此拼出字段说明。
- 输出格式必须是（这就是 `tile-poster.js` `_onAutofillResult`，约 1392 行，读取的结构）：
  ```json
  {
    "selections": { "<single-select 的 sec.id>": "<button.id>",
                    "<multi-select 的 sec.id>": ["<button.id>", "..."] },
    "inputs":     { "<text-input 的 sec.id>": "文字" }
  }
  ```
- 要求：只输出这一个 JSON；只能用给出的 `id`，文案里没提到的项**不要填**（不要编造价格、联系方式）；`toggle`、`file-upload` 类型不填（面板本来就忽略）。面板侧现有的 id 校验保留。
- `temperature` 取低值。

**写法上的硬性要求**：从功能出发写，**不要**拿网上或别处现成的插件提示词来改。

## 验收
