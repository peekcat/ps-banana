# 开发交接：去云化改造（Windows 端开发 + 测试）

> 读者：Windows 端 Agent。从 2026-10-26 起开发和测试都在 Windows 上做，Mac 端不再改代码。
> 依据：`docs/去云化评估.md`（逐项清单、文件行号、风险），本文只讲**做什么、按什么顺序、怎么算做完**。
> 环境：`docs/Windows测试端准备.md`。

## 目标

把插件改成**不连接作者任何服务器**的独立插件 ps-banana：

- **删掉**：账号、积分、充值、夏算力托管、云 Forge、DLSS、Qwen2.1、客服、自动更新、云同步、服务器状态、遥测、公告。
- **保留并保证可用**：自带 Key（BYOK）出图（AJI / GRS / Momo / Others）、本地 Forge、本地 ComfyUI、本地预设 / 布局 / 知识库、其余本地磁贴。
- **修好**三处原本依赖作者服务器的功能：GRS + GPT-Image 带图出图、翻译 / 提示词优化、海报自动填充。

做法是在原代码上**删掉云的部分**，不是把功能挑出来另起炉灶。

## 规矩

1. **分支**：在 `dev/decloud` 上开发（从 `main` 拉）。每个阶段单独成一组提交；阶段验收通过、用户同意后再合进 `main`。`upstream` 分支永远不动，用来和原版对比。
2. **先计划后动手**：每个阶段开工前，先把「改哪些文件、删什么、怎么验证」写给用户，用户确认后再改。做到一半发现比计划大，停下来说明。
3. **屏蔽一直开着**：hosts 和代理的 `REJECT` 规则（见阶段 0）整个开发期间都不撤。
4. **不入库**：Key、`.grs-key.txt`、含 Key 的日志都不能提交。
5. **许可**：保留所有 GPL 许可头，项目继续用 GPL v3。
6. **装 Node.js LTS**，只用来做语法检查：`node --check <文件>`。插件没有构建步骤，所以不用 npm 装依赖。
7. 每个阶段做完，在 `docs/实机记录/` 写一份验收记录（结论 + 逐项结果），不用贴大段日志。
8. 文档和代码对不上时以代码为准，并顺手改文档。

## 阶段 0：准备与基线（约半天）

先把环境调对，再记下**改动之前**的行为，后面回归就拿它对照。

1. **代理屏蔽**：确认 `127.0.0.1:7892` 上是哪个代理软件，用它**持久的**覆写功能（不要改订阅文件）在规则最前面加：
   ```yaml
   - DOMAIN,xiasanqi.cpolar.top,REJECT
   - DOMAIN,xiasanqiforge.vip.cpolar.cn,REJECT
   - DOMAIN,qwentest.vip.cpolar.top,REJECT
   ```
   验证：`curl.exe -sS -m 10 -x http://127.0.0.1:7892 https://xiasanqi.cpolar.top/` 应当**立即失败**，拿不到任何 HTTP 状态码。刷新一次订阅后再测一遍。同时在代理软件的连接日志里看一下，插件的请求到底走不走系统代理。
2. **绕开首次启动的坑**（这两个都是原版的问题，阶段 A 要修掉）：
   - 新手引导会盖一层全屏遮罩，挡住按钮 → 点气泡里的「跳过引导」。
   - GRS 默认是「夏三七托管」模式，必须登录才能用 → 顶栏「⚡ 算力」页切到「自带 Key」，再填 Key。
3. **基线**（原版 6.6.4，`main` 上的代码）：

   | # | 项目 | 预期 |
   |---|---|---|
   | 1 | 启动后 60 秒内 Network 里的全部请求（列出域名和发起位置） | 有打向 cpolar 域名的请求 |
   | 2 | GRS + Banana：文生图、带选区的图生图 | 正常 |
   | 3 | GRS + GPT-Image：纯文生图 | 正常 |
   | 4 | GRS + GPT-Image：带选区的图生图 | 失败。记下提示原文、**有没有照样出了一张图、有没有扣积分** |
   | 5 | 登录、翻译、提示词优化、海报自动填充、云类磁贴 | 失败，记下各自的表现 |
   | 6 | Console 里启动时的报错和警告 | 原样记下，作为「已有噪音」名单 |

   出图前后各查一次余额：`$env:GRS_API_KEY="<key>"; python tools/grs_probe.py credits`

## 阶段 A：删除云服务（3–5 天，大头）

范围见 `去云化评估.md` §3.1、§3.3、§4。要点：

- 整块删掉的磁贴：`tile-cloud`、`tile-dlss`、`tile-qwen21`、`tile-support`、`tile-update`、`tile-sync`、`tile-aistatus`，以及 `login-service.js`。
- 自动更新删干净：`tile-update`、`bootstrap-handlers.js` 里的 `downloadUpdate` / `launchUpdateBat`、`update_plugin.bat`。删完检查 `manifest.json` 里的 `launchProcess` 权限还有没有别的地方在用：没有就删掉；有的话，把允许的扩展名里的 `.bat` / `.cmd` 去掉。
- **`tile-topbar.js` 风险最高**，只能手术式删：登录 UI、会话恢复、公告、托管 / 自带 Key 切换，都混在这一个文件里。
- 算力模式只保留自带 Key：`compute.mode` 默认值改成 `byok`，去掉托管选项，以及所有 `_grsNeedLogin` 分支。
- 遥测：保留一个空实现的 `Telemetry` 桩，不要逐个去删调用点。
- `core/server-config.js` 不能整个删，`fetchWithTimeout` 还有别处在用；只删指向作者服务器的部分。
- Forge 固定为本地模式，删掉「云」开关和扣积分分支（`tile-run.host.js:709-727`）。
- 小改：AJI 地址列表只用本地兜底列表；Momo 链接写死或删掉；网络诊断删掉「夏三七正式服务器」一项。
- 文案：欢迎页、新手引导、问答磁贴里所有「先登录」「托管」「客服」「云同步」相关的内容都要改或删。新手引导中指向已删除区域的步骤也要删掉，否则会卡住。

**验收标准：**

1. 下面的搜索结果为 0（注释也要清掉）：
   ```powershell
   Get-ChildItem plugin -Recurse -File | Select-String -Pattern 'cpolar|OFFICIAL_BASE|DLSS_BASE|/auth/|/api/(update|telemetry|support|presets|aistatus|aiusage|translate|announcement|aji-urls|momo-link|dlss)|login-service|_grsNeedLogin|cloudCompute|cloudGet'
   ```
   这里没包含 `/api/poster/upload-temp` 和 `/api/usage`，它们在阶段 B、C 里处理。范围是 `plugin\` 下**所有文件**（包括 `GPTdev.md` 这类文档）。后面各阶段的搜索都用 `Get-ChildItem plugin -Recurse -File | Select-String -Pattern '...'` 这个写法；`Select-String` 自己没有 `-Recurse` 参数（本文旧版的命令写错了）。
2. 所有 `.js` 文件都能通过 `node --check`。
3. **清空插件数据后重新安装**（删掉 `PluginsStorage\...\PluginData` 目录再加载）：欢迎页和新手引导能顺利走完，没有哪一步卡住，需要用户点界面的步骤都点得到（讲解步骤里遮罩挡住底下的界面是原版的设计，不算问题）；默认就是自带 Key 模式；填入 GRS Key 后，**不经过任何登录界面**就能出图。
4. 启动后 60 秒内，Network 和代理日志里**没有任何**打向 cpolar 域名的请求，也没有打向用户配置的服务商和本地引擎以外地址的请求。例外：展开「信息」磁贴时查一次公网 IP（`api.ipify.org` / `ipinfo.io`），用户主动触发，按使用者决定保留。
5. Console 里除了阶段 0 记下的已有噪音，没有新的未捕获错误。
6. 回归：基线第 2、3 项照常正常；本地预设和布局能加载、能保存；磁贴能拖动、能调大小；设置、账单、网络诊断磁贴能打开、能用；界面上找不到登录、充值、客服的入口。

## 阶段 C：GRS 带图改用新接口（0.5–1 天）

方案已定，见 `去云化评估.md` §5.1：`callGrsGptImageApi` 改为 `POST {base}/v1/api/generate`，`images` 字段填 data URI，`replyType` 设为 `"async"`；然后轮询 `GET {base}/v1/api/result?id=`。删掉 `_uploadRefsToTempServer`，`tile-run` 和海报两处一起改。状态为 `violation` 时按失败处理，并给用户能看懂的提示。第一版**保留** 1.2MB 压缩。

**验收标准：**

1. GRS + GPT-Image 带选区出图成功，而且**结果确实参考了选区**。验证方法：选一块纯色区域，提示词写「把它改成另一种颜色」，结果图里应该能看到对应变化。
2. 海报磁贴走同一条路径，同样成功。
3. 这次出图过程中，Network 里只有发往 GRS 节点和结果图片域名的请求。
4. 搜索 `_uploadRefsToTempServer|upload-temp|support.deviceId` 结果为 0。
5. 故障路径：Key 填错、触发违规（`violation`）、网络断开这三种情况，界面都要给出能看懂的提示，**不能静默出一张没参考选区的图**。
6. 基线第 2、3 项回归仍然正常。

## 阶段 B：翻译 / 提示词优化 / 海报自动填充改为自带 Key 直连（1–3 天）

这三个功能原来都把请求转给作者服务器，系统提示词也放在作者那边。改为直接调用户配置的 OpenAI 兼容接口 `/v1/chat/completions`。仓库里有现成写法可以照抄：`tiles/tile-chat.js:291`、`tiles/tile-light-splitter.host.js:128`。海报那里的用量上报 `/api/usage` 直接删掉。

- 配置方式（新加一个「辅助 LLM」配置项，还是复用 Others 服务商的配置）由用户决定。开工前先问。
- **系统提示词不要把作者的原文提交进仓库。** 那些提示词是作者服务器上的内容，从来没有按 GPL 公开过，而仓库是公开的。可以自己重写，或者让用户的备份留在本地、不入库（例如放进被 gitignore 的文件，从本地读取）。具体怎么做和用户确认。

**验收标准：**

1. 配好辅助 LLM 后，三个功能都能正常用，效果和原版大致相当。
2. 没配置时，给出明确提示「请在设置里配置辅助 LLM」，不报底层错误。
3. 整个过程 Network 里只有发往用户所配 LLM 地址的请求。
4. 搜索 `/api/usage` 结果为 0，阶段 A 的那条搜索仍然是 0。
